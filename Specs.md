Rol y objetivo. Eres el desarrollador principal de Memoria Viva, una plataforma web ficticia de la Fundación Legado Vivo (Palmares, Costa Rica) para preservar y narrar memorias de personas adultas mayores. Construye un MVP funcional de punta a punta, con la IA simulada, para una demostración de 10 minutos. Un recorrido completo que funcione y se vea bien vale más que muchas funciones a medias. Si algo no está especificado, elige la opción más simple y anótala en NOTAS.md; no inventes funciones.

Stack. Frontend: React, Vite, TypeScript, Tailwind CSS y componentes Radix/shadcn. Backend: Python 3.12, FastAPI, Pydantic, SQLAlchemy y Alembic. Base de datos: PostgreSQL 16. Todo con Docker Compose (web, api, db) y configuración por .env. Monorepo con apps/web, apps/api, seed y docker-compose.yml. Usa la skill frontend-design para todas las pantallas.

Reglas del dominio que nunca se rompen. Una memoria sin consentimiento registrado no se puede procesar, publicar ni usar en el narrador. La visibilidad por defecto es privada y las opciones son privado, familiar y público. Cada memoria tiene una sola base de conocimiento y los datos de memorias distintas nunca se mezclan; toda consulta a entidades, relaciones y aportes filtra por memoria y por permisos a través de un único módulo de privacidad que usan la búsqueda, el narrador y la carga. El material original nunca se modifica: guarda su hash SHA-256 y las correcciones van aparte. Solo el contenido validado por el Gestor de datos alimenta la base de conocimiento. El narrador responde solo con lo que está en la base de conocimiento de esa memoria, se identifica siempre como inteligencia artificial, cita la fuente (aporte, autor y fecha) y, si no tiene información, responde "no cuento con esa información" sin llamar al modelo ni inventar.

Roles y pantallas. Cuatro roles: Usuario, Digitalizador, Gestor de datos y Administrador. Pantallas: P01 inicio de sesión, P02 mis memorias, P03 consentimiento y privacidad, P04 carga de relatos (texto, audio y foto), P05 revisión y validación con el original junto al texto procesado, P06 buscador, P07 narrador con botón "Ver fuente primaria", y una pantalla simple de usuarios y roles. Cada rol ve solo lo suyo.

Modelo de datos mínimo. usuarios (con rol), memorias (titular, tipo, estado, visibilidad, póstuma), consentimientos (memoria, modalidad, evidencia, fecha), aportes (memoria, autor, tipo, estado, archivo, hash), procesamientos (aporte, texto o descripción, versión validada), entidades y relaciones (memoria_id, aporte de origen, fragmento), colecciones y su relación con memorias, y bitácora de auditoría.

Capa de IA. Define cuatro interfaces: transcripción, análisis de imágenes, modelo de lenguaje y voz. Implementa por ahora solo la versión simulada, que devuelve contenido de ejemplo coherente con los datos semilla, y selecciónala con AI_MODE=mock. Deja la estructura lista para añadir la versión real sin tocar el resto del código. La voz usa la síntesis del navegador.

Datos semilla. Crea dos memorias ficticias con personas inventadas de Palmares, cada una con consentimiento, un texto, una foto de ejemplo y un audio simulado, más un usuario por rol con contraseñas de demostración.

Diseño de interfaz. Pensado para personas adultas mayores y sus acompañantes: letra base de 18 px ampliable hasta el 200 %, contraste mínimo de 4.5:1, botones de al menos 48 px, una acción principal por pantalla, máximo tres niveles de navegación, íconos siempre con texto y mensajes claros en español. Evita el aspecto genérico de plantilla de IA: sin degradados morados ni tarjetas idénticas repetidas; define una paleta cálida y sobria y una tipografía legible, y aplícalas con tokens.

Orden de trabajo. Primero la estructura del repositorio, Docker, base de datos con migraciones y datos semilla. Segundo, autenticación y roles. Tercero, memorias con consentimiento y privacidad. Cuarto, carga de aportes y procesamiento simulado. Quinto, revisión y validación y construcción de la base de conocimiento. Sexto, buscador y narrador con citas y "Ver fuente primaria". Séptimo, administración básica y pulido visual. Haz un commit por hito y verifica el recorrido completo antes de pasar al siguiente.

Criterio de aceptación. Un Digitalizador crea una memoria con consentimiento, carga un relato, el Gestor lo revisa y lo valida, y un Usuario le pregunta al narrador, recibe una respuesta con fuente y abre el original. Una pregunta sin información recibe "no cuento con esa información", y una memoria privada no aparece para otro usuario. Incluye pruebas automáticas de estas reglas de privacidad.
